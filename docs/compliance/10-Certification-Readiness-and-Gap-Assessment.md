### 1.2 Purpose and scope of this document

This document is an **honest, internal self-assessment** of SwiftLoan's readiness to pursue
**ISO/IEC 27001:2022 certification** and a **SOC 2 (Trust Services Criteria) examination**. It
consolidates the management-system gaps (G1–G4), the repository/CI hygiene gaps (G5–G12), and the
product/security concerns (C1–C14) recorded in the Audit Brief, and maps each to the relevant clause
or criterion.

It is deliberately **not celebratory.** A large body of documentation and CI automation has been
put in place in this pass, which materially improves the *design* of the control environment. But
certification is gated by two things this document is explicit about: (a) the **product/security
remediation backlog C1–C14 is still open**, and (b) neither framework can be certified until an
**operating-effectiveness evidence period** has elapsed and been examined by an accredited/licensed
external party. This is a readiness document, **not a certificate** (see §10).

## 2. Executive Summary

**Headline:** SwiftLoan now has strong documentation and security automation in place, but
**product/security remediation (C1–C14) and the operating-effectiveness evidence period are the
gating items** before either ISO/IEC 27001:2022 certification or a SOC 2 Type II report can be
achieved.

### 2.1 Overall readiness posture

| Framework | Design readiness | Operating readiness | Certifiable today? |
|---|---|---|---|
| **ISO/IEC 27001:2022** | Partial → Good (ISMS documented; SoA drafted; policies drafted in Doc 08) | Weak (controls not yet operating; several Annex A controls Open due to C1–C14) | **No** — not ready for Stage 2; Stage 1 (documentation review) feasible after Doc 08/09 finalized |
| **SOC 2 (Security + Availability + Confidentiality + Privacy)** | Partial (system description drafting in Doc 08; TSC mapped) | Weak (no evidence period; multiple CC6/C1/P criteria Open) | **No** — Type I possible only after C1–C14 P0/P1 fixes land; Type II requires 3–12 months of evidence |

### 2.2 What is genuinely strong now

- **Management-system documentation** exists as a coherent set (Docs 01–10), with a verified fact
  base (`_AUDIT_BRIEF.md`) and a live control-status feed (`COMPLIANCE-STATUS.md`, auto-generated by
  `scripts/compliance/compliance_sync.py`).
- **Security automation in CI is implemented** this pass: SAST (CodeQL), secret scanning (gitleaks),
  dependency/SCA scanning (Dependabot + `npm audit`), code ownership (`CODEOWNERS`), PR governance
  template, vulnerability-disclosure policy (`SECURITY.md`), and an IP `LICENSE`. These directly
  close gaps G5–G11 and provide durable evidence for ISO A.8.8/A.8.25–28 and SOC 2 CC7.1/CC8.1.
- **A Statement of Applicability (Doc 05)** covering the 93 Annex A:2022 controls exists, so the
  scope of applicable controls is defined rather than open-ended.

### 2.3 What is gating certification (be explicit)

1. **Open product/security concerns C1–C14.** Several are P0 (committed live API key C5, demo-OTP
   bypass C3, default admin credential C4, fail-open secrets C6) and directly fail ISO A.8.5/A.8.24
   and SOC 2 CC6.1. **No auditor will certify with these open.** Status per
   `COMPLIANCE-STATUS.md`: **0 of 9 machine-tracked controls Implemented.**
2. **Operating-effectiveness evidence period.** ISO Stage 2 and SOC 2 **Type II** both require that
   controls be shown to have *operated* over time — typically **3–12 months** of retained evidence
   (tickets, logs, review records, access reviews). SwiftLoan has essentially **zero elapsed
   evidence period** for the newly documented controls.
3. **Governance documents in flight.** Doc 08 (ISMS manual/policies) and Doc 09 (by-design
   principles) are **Drafted, not Approved.** ISO Clauses 5–7 require top-management-approved,
   version-controlled documented information.
4. **A repo-settings action remains (G12):** branch protection on `main` and GitHub secret-scanning /
   push-protection **enablement** — the workflow files exist, but the enforcement toggles are a
   repository-administration task the team must complete (see §7).

### 2.4 Bottom line

SwiftLoan is **credibly on a certification path but is not yet certifiable.** Realistic earliest
timelines (see §8): **ISO 27001 Stage 1** in ~2–3 months (after Docs 08/09 approved and P0/P1 fixes
land); **ISO Stage 2** and a **SOC 2 Type I** at ~4–6 months; a **SOC 2 Type II** report no earlier
than ~7–15 months, dictated by the chosen evidence window.

### 5.3 Type I vs Type II

| | **SOC 2 Type I** | **SOC 2 Type II** |
|---|---|---|
| Question answered | Are controls **suitably designed** at a point in time? | Do controls **operate effectively** over a period? |
| Evidence period | Single "as-of" date | **3–12 months** of continuous evidence |
| SwiftLoan feasibility | Possible **after P0/P1 of C1–C14 land** and Doc 08 approved | **The gating item** — cannot start the clock until controls are live |
| Recommended path | Do Type I first to validate design | Then Type II over a 6-month initial window |

**Gating item (explicit):** the **operating-effectiveness evidence period (3–12 months)** is the
principal constraint on a SOC 2 Type II report. Even with all C1–C14 fixed tomorrow, a Type II report
cannot be issued until controls have demonstrably operated across the chosen window with retained
evidence (access reviews, change tickets, logs, incident records, vulnerability-scan results).

### 5.4 Sub-service organizations & CUECs

- **Sub-service organizations** (to be treated via the **carve-out** method, documented in **Doc 08**):
  - **Render** (application/database hosting) — inherits physical, environmental, and
    infrastructure controls; obtain the host's SOC 2 / ISO attestation and map to A.7 / A1.
  - **Ello / Getello ("Ruby" voice AI)** — third-party processor receiving live screen context;
    **carve-out with a required DPA** (C12) and **CUECs** for consent-gating and redaction (C2).
- **Complementary User Entity Controls (CUECs)** — controls that **partner lenders/NBFCs** and other
  user entities must operate for SwiftLoan's controls to be effective (e.g., their own KYC/approval
  decisioning, bureau-pull consent handling, secure receipt of leads). To be enumerated in Doc 08.

## 8. Consolidated Remediation Roadmap to Certification

Phased plan from current state to certification. Timelines are **indicative** and assume dedicated
resourcing. "Self-declare" = SwiftLoan can complete internally; "External" = requires the
accredited/licensed third party.

### Phase 0 — Foundation (Weeks 0–3) · *Self-declare*
- **Approve Doc 08 (ISMS manual/policies) and Doc 09 (by-design principles)** — move from Drafted to
  Approved with top-management sign-off (ISO 5.1/5.2). *Owner: CISO + CEO.*
- Convene **ISMS Steering Committee**; issue Information Security Policy; publish RACI; formally
  appoint **DPO / Grievance Officer**. *Owner: CEO/CISO.*
- Approve **SoA (Doc 05)**, risk methodology, and a formal **Risk Treatment Plan** derived from
  C1–C14 with owners and target dates. *Owner: CISO + DPO.*
- **Complete G12** repo-settings action (branch protection + secret-scanning/push protection). *Owner:
  Platform/DevOps lead.*

### Phase 1 — Remediate C1–C14 (Weeks 1–12) · *Self-declare*
Sequenced by the Audit Brief priorities (P0 → P3):
- **P0 (Weeks 1–3):** rotate & purge committed Ello key (C5); disable `DEMO_LOGIN`/OTP bypass in prod
  (C3); remove default admin creds + add MFA (C4); redact sensitive values from voice `page_context`
  (C2); fail-closed secrets (C6). *Owner: Backend + Security.*
- **P1 (Weeks 2–8):** tokenize/encrypt PAN + de-duplicate (C1); DB encryption-at-rest + encrypted
  backups in India region (C12); strict CORS allow-list + rate-limit/WAF (C7); wire consent
  end-to-end (C2/C9/C10); admin tokens → httpOnly cookies + RBAC (C11); client secure input + PAN
  masking (C14); voice `wss`/`https` only + DPA (C13/C12). *Owner: Backend + Mobile + DevOps + Legal.*

## 10. Statement on Certification Authority

This document is an **internal readiness and gap assessment only. It is not a certificate,
attestation, or assurance report, and it does not confer ISO/IEC 27001 certification or a SOC 2
report.**

- **ISO/IEC 27001 certification** can be granted **only by an accredited third-party certification
  body** following a successful Stage 1 (documentation) and Stage 2 (operating-effectiveness) audit.
  No internal document or self-declaration substitutes for it.
- **A SOC 2 report** (Type I or Type II) can be issued **only by an independent, licensed CPA firm**
  performing an examination under AICPA attestation standards. Type II additionally requires an
  elapsed **operating-effectiveness evidence period (3–12 months)**.
- Until those external engagements are completed, SwiftLoan must **not represent itself as "ISO 27001
  certified" or "SOC 2 compliant."** Permissible interim statements (e.g., "ISO 27001 readiness in
  progress") must be validated against the marketing-claims matrix (Doc 06) and legal sign-off (P3).

As of this assessment, the open product/security concerns **C1–C14** and the absence of an elapsed
operating-effectiveness evidence period mean SwiftLoan is **on a credible certification path but is
not yet certifiable.**
